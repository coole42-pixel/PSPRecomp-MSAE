# Phase 12 correctness fixes (verified)

2026-10-02. Verified scope: shadow correctness, string lookup, and normal profile/menu/race progression, with the splatter artwork preserved.

The evidence and executable hash below record the verified software baseline. The subsequent hardware renderer and current launcher are documented in [native D3D12 rendering](PHASE12_D3D12.md).

## Evidence that changed the diagnosis

- A run without boot/movie-scene skips reaches the memory-stick notice and waits for confirm. It is not a loading deadlock. See `out/motorstorm/phase12/fixes/title-savedata/frame_6.png`.
- The system parameter for confirmation incorrectly returned 0 (Circle) while its comment claimed Cross. Cross is value 1; this is corrected and regression-covered.
- The normal notice continuation requests savedata mode 11. It previously stopped on missing `sceUtilitySavedataInitStart` (0x50C4CD57). The real savedata service now lists actual profile directories, persists/reloads payloads, validates memory and paths, and follows the utility lifecycle. A test round trip passes.
- Targeted loader tracing proves the common string table is mounted at 0x08C57900 with 132 entries on the normal path. The table-0-to-table-3 alias workaround has been removed. Trace: `menu-mpeg-size-console.txt` under the fixes directory.
- MPEG stubs claimed success while leaving query sizes and decoder handles uninitialized. Real MPEG structures, guest feeder callbacks, timestamps, YCbCr/CSC and the in-process media decoder now decode the actual PMF assets. GE block transfers copy decoded pictures into VRAM.
- The VTYPE/blend/depth heuristic that fabricated shadow UVs, alpha and depth bias was removed. The constant-UV alpha-blended regression failed before removal and passes now. Correct shadows now come from the guest's own projection and alpha texture.
- Callback notifications now run on the PSP owner thread. `WaitThreadEndCB` previously stranded a pending callback needed to release the joined movie worker's semaphore; the two-thread join dependency regression passes with callback-aware joins.
- A host audio-drain workaround prematurely signaled the guest's `SoundEvent` bit 4. Audio tracing proved that SoundThread reclaimed Output2 before the movie could reserve it, then lost its reservation when the movie released it. This game-specific event signal was removed. The guest now performs its own movie-to-mixer handoff; audio/event isolation is regression-covered.
- `CancelSema` incorrectly treated a1 as a pointer and filled the count to maximum. It now uses a1 as the new count and a2 as the waiter-count output, with negative count restoring the initial count. Regression passes.
- Timer preemption previously ignored dispatch suspension and CPU interrupt suspension. These critical-section guards now retain their state and gate preemption; both regression scenarios pass.
- The final AVC decode drain incorrectly returned `NO_DATA`; the codec now completes that AU successfully with frame status zero, and the next AU request reports EOS. The former error path stranded a movie source mutex. The real-asset integration test decodes all 1345 background PMF pictures and verifies both boundary results (`tests-pmf-eos-audio-queue.txt`).
- Output2 marked a buffer drained immediately after its producer was parked. Clock-backed DMA deadlines now retain the in-flight count, make premature release report busy, and allow release after drain. The regression passes; `normal-race-audioqueue-console.txt` shows the background cleanup's release returning busy rather than stealing SoundThread's channel.
- **Shadow root cause:** six PSP `R_MIPS_16` relocations were unsupported. They are the low members of HI16/VFPU memory pairs. In particular, stores at guest PCs `0x088EF1BC` and `0x088EF1C8` wrote to the wrong addresses, leaving projection rows at `0x08AAA9B0/0x08AAA9C0` zero. The guest consequently generated center UVs for every receiving terrain vertex and drew broad black patches. This was traced through raw GE vertices, RAM write watches and IDA's caller analysis. The generic loader now supports type 1 and pairs HI16 with it, including signed-low carry and retained VFPU selector bits. Regression fails before (`tests-rel16-before.txt`) and passes after (`tests-rel16-after.txt`). AOT regeneration rewrites four units (`regenerate-rel16.txt`). The final run reports all 90500 relocations handled with zero invalid/unsupported entries; its write trace shows live projection coefficients, and its rendered frames show soft vehicle shadows in place of the broad polygons. The PSP pairing behavior is also documented in [PPSSPP's ELF loader](https://github.com/hrydgard/ppsspp/blob/master/Core/ELF/ElfReader.cpp#L164).
